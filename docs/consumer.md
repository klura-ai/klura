# Consumer boundary

`@klura/runtime/consumer` is the dependency-clean entrypoint for the local execution product. It does not import runtime state, discovery phases, audits, saved strategies, health, agent code, or the MCP host. The root `@klura/runtime` entrypoint remains the complete factory-compatible surface.

The entrypoint currently owns the public trust primitives shared by the registry compiler, installer, and consumer adapters:

- branded canonical identifiers, SemVer versions, closed runtime ranges, SHA-256 digests, session names, and RFC 3339 instants;
- RFC 8785-compatible canonical JSON rendering and SHA-256 digesting;
- bounded strict JSON parsing with duplicate-key rejection; and
- a strict bounded JSON Schema subset with no remote references or runtime hooks; and
- a closed value-expression AST for package request construction; and
- strict signed-registry index parsing and Ed25519 verification; and
- a local content-addressed package store with atomic installed-state activation.

The signature covers canonical JSON bytes of `payload` only. The envelope is strict: it accepts schema version `1`, the compiled `registry-v1` key ID, unpadded base64url signatures, bounded package/version/capability maps, byte-equal map keys, a seven-day maximum validity window, immutable digests, and the closed runtime-range representation. Registry envelopes are bounded to 12 JSON levels; a public package artifact has its own 32-level limit because a fully declarative collection graph legitimately nests deeper than its catalog entry.

The registry client keeps one exact signed-index cache at `registry/index.signed.json`. A refresh uses one HTTPS request with redirects disabled, one deadline, bounded streaming bytes, signature/time-window verification, then private-temp-file + fsync + atomic rename. A failed or invalid refresh never overwrites an already usable cache.

`PackageInstallerV1` always refreshes the registry before resolving a version. It rejects absent, withdrawn, or runtime-incompatible versions before package download; download is same-origin, redirect-free, exact-length, and digest-verified. Before activation it compares the package's derived public capability projection with the signed index entry, then commits the immutable artifact and active pointer without sending target-site traffic.

The node HTTP execution boundary evaluates only the signed data AST after validating caller input. Each target dispatch, including every redirect hop, takes an origin-scheduler permit and consumes the invocation's remaining signed request budget. The scheduler merges simultaneous policies conservatively and enforces concurrency, token rate/burst, minimum delay, and a typed transient-failure circuit. It keeps FIFO order within one workload and round-robins queued workloads on the same origin, so one scrape cannot monopolize a shared origin. Circuit cooldown and transient-failure state live in a private, strict local file so a daemon restart does not erase active hammer protection. One deadline covers scheduler admission, DNS resolution, HTTPS connection, response streaming, and redirects. The boundary resolves all DNS answers before a connection, rejects loopback/private/link-local/multicast and IANA special-use address space, pins HTTPS/TLS to one validated address, owns `Host` and transfer headers, bounds response bytes and request time, and revalidates every redirect against the signed request-origin set. It classifies malformed JSON, timeout, cancellation, oversized response, transport failure, and blocked egress as typed failures; response wording is never used for a decision. An http strategy declares how its response becomes the object the outcome contracts classify: a `json` projection parses the body strictly, and an `html` projection applies a declared, data-only extraction — named CSS selectors reading trimmed text or one attribute, singly or as arrays, optionally as row groups with per-row fields — through the same standards-mode selector validator the browser DOM projection uses, so a static HTML page is read in Node without a browser and arrives as one JSON object whose shape the declaration alone fixes: a missing single match is `""`, a missing row group `{}`, a missing multiple match `[]`. Every target request carries `user-agent: klura/<runtime version>` unless the package declares its own, since several public APIs refuse an anonymous client outright. The package parser rejects an endpoint, query, or header expression that can never evaluate to a string — a non-string literal, an object or array, or an input whose declared schema type is not string — and names `to_string` in the rejection, so a page counter that must ride a query parameter cannot ship as an integer.

The scheduler implementation is shared with trusted local execution. A factory `fetch` strategy in Node or browser context, and every `fetch-extract`, `page-extract`, or browser prerequisite navigation with a declared URL, takes the same per-home, per-origin permit before target traffic. Their default policy is a 30-second request deadline including body streaming, four concurrent requests, five admissions per second, a burst of four, no more than five redirect hops, and a five-failure circuit over sixty seconds with a sixty-second cooldown; users may lower or tune those values through `traffic.*` in local config. Node aborts the request when that deadline expires, follows redirects manually so each hop takes its own permit, and does not reuse a permit until the prior redirect body is cancelled. A Node WebSocket handshake shares the matching HTTP(S) origin permit for its full bounded connection, send, and optional-ack lifetime. Browser fetches receive the same in-page abort deadline; and first-party browser navigation passes that exact deadline to Playwright before its permit can be released. A signed public-package policy and a local policy for the same origin merge conservatively, so parallel factory and consumer work cannot create separate admission pools. Signed browser execution continues to use its signed egress rules and the same scheduler.

The consumer browser kernel is separate from the discovery driver. Each browser-navigation, browser-context HTTP, or reviewed page-script call starts an isolated Chromium context behind a per-context loopback CONNECT proxy with an unguessable credential: it accepts only declared HTTPS host/port pairs, resolves every tunnel itself, rejects any non-public DNS answer, and pins the upstream socket to the selected numeric address. Before navigation, the context installs CDP request and response interception, disables cache, service workers, downloads, popups, WebSockets, WebTransport, non-proxied WebRTC, extensions, and direct-proxy bypass. A context-wide request guard aborts traffic from every page target except the one carrying the policy-bearing CDP boundary, so an `about:blank` popup cannot navigate ahead of page-scoped interception. Every request the task itself issues — the navigation, each declared interaction, a runtime request, or page-script traffic — must match one exact signed egress rule for phase, origin, method, resource type, path, and query shape, reserve the shared origin scheduler, and stay inside signed per-rule, per-request, whole-task, response, and wire budgets; an undeclared request in any of those phases fails the task as `request_blocked` with an egress diagnostic naming the phase, origin, path, and query keys. A sub-resource the page fetches on its own — a stylesheet, script, image, or font no rule admits — is refused at the CDP layer and the page carries on without it; the boundary counts such refusals but they never fail the task, so a package declares the traffic it needs rather than every asset a site happens to reference. The boundary owns the page's Fetch domain, so it also answers the pinned proxy's authentication challenge itself and cancels any other challenge. Browser resource rules may admit a bounded `POST`; a CDP `Ping`, including a `navigator.sendBeacon` request, is represented by the resource-phase type `ping` and requires its own exact rule and budgets. CDP `Other` is outside the public resource schema and remains blocked. Navigation and interaction rules remain `GET`/`HEAD` only. An `OPTIONS` request is never independently declarable: the runtime admits only a CDP `Preflight` resource carrying the exact canonical `Access-Control-Request-Method` for one signed resource-phase Fetch/XHR rule at the same origin, path, and query shape. The preflight must have a zero-byte body and consumes the target, scheduler, rule, response, and wire budgets of that rule, so the manifest must budget both it and the resulting request. Preflights in every other phase are blocked. A browser-context HTTP strategy first performs one signed same-origin bootstrap navigation, then the runtime—not package code—issues its exact GET or POST through a dedicated `runtime_request` rule. The response interceptor bounds a body before the page receives it, then fulfills the paused request from that bounded buffer. Login additionally accepts a request body only when CDP exposes a structurally complete bounded representation; it applies the signed per-rule, per-request, and whole-login body limits before the request continues.

Ordinary browser-navigation packages remain declarative: signed URL expression, event-driven wait, standard-CSS DOM projection, bounded action program, and optional authentication-realm declaration. Each action targets exactly one declared main- or child-frame element, has a structural egress expectation, and can only click, fill/select a bounded string, press Enter, or scroll one viewport. Repeats stop only on mutually exclusive structural DOM predicates; every action mismatch is a typed `browser_interaction_failed` result.

`browser_page_script` is a separate maintainer-reviewed profile for a read capability that cannot be represented by the declarative browser ABI. Its exact source bytes and SHA-256 digest are covered by the package manifest. It admits `authentication.mode:"none"` only, exactly one navigation origin, main-frame execution, same-origin navigation and preparation, and same-origin `page_script` rules limited to GET/POST XHR or Fetch. The executor rechecks the main-frame origin immediately before source starts. The signed program declares its input expression, object-or-array result shape and required object keys, expected rule IDs and request-count range, request-body ceilings, response ceilings, and total target-request budget. Its per-program request-body ceilings must fit within the enclosing browser policy's whole-task, single-request, and per-rule ceilings. Before target scripts run, the runtime installs a non-replaceable main-world runner whose closure captures pristine validation and encoding intrinsics. Reviewed source therefore retains local `js-eval` access to page-defined globals without gaining access to validator state; it is never evaluated in the Node host. Its return is checked against the signed result shape and encoded as finite bounded plain JSON by the sealed runner, then byte-bounded, strictly reparsed, and shape-checked again by the host before the ordinary signed outcome contracts classify it. The sealed runner returns a closed success-or-failure envelope, so a byte ceiling becomes `response_too_large`, a signed shape violation becomes `response_contract_mismatch`, and no runtime decision depends on exception wording. Page-program results use the local page-script response semantics: synthetic status `200`, empty headers, and media type `application/json`; bootstrap response metadata is not exposed to outcome matchers. When the awaited program returns, the network boundary seals: deferred requests are blocked rather than reclassified as background page resources. Public Chromium is launched with its OS sandbox required; a platform that cannot provide it fails as `browser_unavailable`. The source digest is not a static-analysis security claim; registry review, the isolated sandboxed page, exact egress admission, byte accounting, and structural output contracts are the security boundaries. Package content still cannot contain credentials.

`PublicCallerV1` derives one invocation deadline, counts target attempts, evaluates every response against the signed structural outcome contracts, and permits retry only for an explicitly declared transient class. Retry delay is bounded signed exponential backoff with non-negative jitter; a declared header/JSON retry value may raise that delay only when the capability opts in. A classified semantic outcome terminates the call; unclassified, ambiguous, verification, timeout, and transport results can move to a later same-package strategy, but block/cancellation/input failures cannot silently fall through.

An outcome `json_object` projection may compose named JSON-pointer values and declared JSON-array maps into one verified object. Cursor-based collections use it to return typed items beside an exact structural continuation token; no runtime path derives a cursor from response text or links.

```ts
import { verifySignedRegistryIndex } from '@klura/runtime/consumer';

const index = verifySignedRegistryIndex(candidate, registryPublicKey);
```

`RegistryCatalogV1` projects only verified signed fields into deterministic package summaries. A first search page refreshes once and may fall back only to a currently valid cache; a subsequent cursor page reads the exact cached source digest without refreshing. Query normalization is Unicode NFKC plus neutral Unicode lowercasing, followed by whitespace tokenization. Every token must be a contiguous substring of one signed catalog field; there is no ranking model or semantic expansion. Cursors bind the canonical query, source digest, and last package ID, so replacing or removing the cache produces `cursor_stale` rather than a mixed catalog page.

`show` refreshes once under the same cache rules, resolves one stable or exact version, then downloads and validates its content-addressed package without changing local installation state. The package ID, version, manifest digest, and capability projection must all match the signed index. It returns either package metadata or an explicit capability contract; strategy details, request construction, controls, and discovery evidence are never projected.

`ConsumerRegistryServiceV1` converts `search`, `show`, and `install` into one canonical result family for CLI, SDK, and MCP adapters. It gives expected registry, selector, and local-state failures a fixed operation/code/retryability envelope, while an install result records both the active artifact and the active pointer it replaced. The CLI and consumer daemon both construct the same runtime-owned authority for `https://registry.klura.ai/v1/index.signed.json`, using the Ed25519 public key compiled into the runtime. User configuration never supplies a registry URL or key.

`KluraConsumerClientV1` is the consumer SDK facade. It takes separate structural `{ package_id, capability }` selectors, never parses a combined package string, and does not fall back to discovery when a package or capability is unavailable. Every registry, installed-package, call, run, and run-inspection method crosses the one local daemon; the SDK owns neither a package-store reader nor a run-store reader. The SDK resolves a relative file-output path in the calling process before IPC and sends the daemon only the normalized absolute destination. `run(..., { signal })` is the foreground convenience: observer cancellation durably requests `sdk_cancel`, then waits for the ordinary terminal result; `cancelRun` is the explicit durable cancellation operation. Each start, resume, cancel, and discard carries one canonical `op_v1_…` operation ID. The daemon stores its exact command digest and result before replying, so a retry with that ID replays the same result without a second run or mutation; a caller that needs to retry after losing its own process state supplies its operation ID explicitly.

The existing MCP server now advertises the consumer operations beside its compatibility discovery tools. Consumer tools are listed first and return their canonical bounded object as `structuredContent`; their short text block is only a renderer. The MCP process is an adapter only: it has no package-store, registry, or run-store access and reaches the same local daemon through the consumer facade. The adapter rejects unknown keys before facade invocation, never turns a typed failure into a discovery request, and replaces an otherwise oversized response with typed `output_too_large_for_adapter` rather than truncating data. Tool annotations describe read-only, idempotent, destructive, and target-reading operations so the host can apply its ordinary confirmation policy. An MCP file-output path must already be absolute because an MCP host has no caller working-directory contract.

Every consumer tool input is defined once in `consumer/contracts/tool-contracts.ts` and validated at each trust boundary from that one definition. The module holds one argument contract per consumer tool and one wire-body contract per daemon consumer route, both built from a shared field catalog that delegates to the existing public-contract parsers (`parsePackageId`, `parseRunId`, `parseScrapeCallerBounds`, …) rather than re-expressing identifier grammar. The published MCP `inputSchema` of each consumer tool is generated from its argument contract — `start_scrape_run.options` publishes its complete ten-field shape, including caller bounds and the named-limit map — so the agent-visible schema cannot drift from what the handler enforces. The SDK facade validates the same argument contracts before IPC, the daemon validates each route body with its wire contract (closed keyset, every key present, `null` meaning absent), and the CLI derives its flag bounds from the same constants. Numeric bounds and byte ceilings live in `public/contracts/consumer-bounds.ts`; the domain caller-bounds parser in `public/contracts/scrape-policy.ts` reads the same entries, so every boundary caps each caller bound at 3,600,000, each named caller limit at 1,000,000, and the named-limit map at 64 entries — a value an adapter accepts is a value run planning admits. Fields whose value-level validation belongs to a typed-failure service (registry search/show/install selectors, listing cursors and limits) pass through the wire contract's keyset check and keep their typed `consumer_failure` envelopes from that service. `runtime/test/consumer-contract-parity.test.js` locks the generated schemas, the schema/parser keyset parity, and the adapter-versus-domain bound equality.

The production registry authority remains a release-provisioned trust root. Consumer configuration does not replace it.

`@klura/runtime/factory-compiler` is the dependency-clean factory-facing build entrypoint for a repository `package.source.json`. `compilePublicPackageSource()` accepts only the complete public package shape without a manifest digest, derives compiler-owned page-script source digests and collection item bounds, derives the manifest digest over canonical bytes, reparses the finished artifact, and returns the exact bytes that a release workflow may hash and sign. A source file must set each reviewed page program's `source_digest` to null; retaining a hand-authored digest is rejected, so edited source cannot accidentally keep stale review metadata. A package capability is either `public` or `internal`: only public capabilities enter the signed catalog projection and may be selected by `show`, `call`, or `run`; an internal capability has no collection of its own and may be used only as a declared safe-read collection task. This lets one public collection surface own simple caller input while its paging or detail primitives remain implementation detail. For a collection, the compiler also derives a finite canonical-JSON upper bound for each item schema when that schema proves one; source files leave `inline_output_bound` null and cannot author a bound themselves. Public-package validation recomputes the same value, so a changed schema cannot retain a stale bound. The catalog manifest and the repository layout each have one shared owner: `public/contracts/registry-catalog.ts` defines the `registry.json` manifest contract and the release source path grammar, and `factory/public-package/tools-layout.ts` defines the `tools/<package_id>/` tree grammar from those same constants. The platform exporter writes through them, and the PR path gate, static registry builder, and fixture verifier read through them, so neither manifest keys nor directory shape can drift between writer and readers.

`exportReviewedLocalPageScriptStrategySource()` is the narrow bridge from an already-saved local factory strategy to that public source ABI. It accepts only a read-only local `page-script` whose result is exactly one main-frame, per-call `js-eval` prerequisite selected by `response.from`; the bind must match, the return shape must be an object, and iframe, refresh, HTML extraction, authentication, and multi-prerequisite chains are rejected. The caller supplies the destination capability's public `input_schema`. Every local placeholder must resolve through required declared properties to a string, number, integer, or boolean, which proves that local interpolation and the public value-expression AST have the same behavior for every valid call; object, null, optional, and unsupported placeholder paths fail export. The exporter preserves the local required result keys in the signed program result shape, structurally compiles the local URL and `args_template`, and wraps the exact saved expression as reviewed main-world source. The maintainer must still author the public output schemas, outcome cases, URL wait, egress rules, request counts, body limits, traffic policy, and catalog data. Passing that fragment through `compilePublicPackageSource()` and the ordinary registry compiler makes it installable; export itself never signs or publishes anything.

`exportPlatformPackageToTools()` is the factory-side orchestration boundary above that narrow exporter. It reads the explicitly reviewed subset of active capabilities for one saved platform, leaves unreviewed local primitives internal, requires an exact structured review contract for typed outcomes, egress, budgets, catalog data, and fixture inputs, then compiles and executes every fixture through `PublicCallerV1`. Only declared success outcomes are accepted. It writes one create-only `tools/<package_id>/` directory after all smoke calls pass; a failed audit writes nothing. The directory contains reviewed source, registry metadata, and call fixtures captured from the verified consumer responses. This boundary never signs, installs, publishes, or performs Git operations.

`compileRegistryReleaseEntry()` combines compiled package bytes with explicit catalog metadata and a trusted registry origin, then derives the artifact URL, byte length, digest, manifest, runtime range, and public capability projection. `compileStaticRegistryIndex()` accepts only those compiled entries and produces the exact validated payload; `signStaticRegistryIndex()` signs only its canonical payload bytes with a caller-supplied release key. The low-level compiler functions operate only on values supplied by the caller and retain no signing key. The platform exporter may read local strategies and execute reviewed smoke fixtures, but it never infers catalog or contract data from prose.

`PackageStoreV1` retains the exact verified package JSON bytes at `packages/<package-digest>/package.json`. `installed.json` is a separate atomic map from package ID to an active immutable artifact, its provenance, runtime range, and installation instant. Provenance is a tagged union rather than a flag: a registry install carries `{kind: 'registry', source_index_digest}` and a locally authored install carries `{kind: 'local', source_digest}`, so a local artifact has no `source_index_digest` key for a reader to misread. Install/remove obtains a local activation lock (the shared owner-file lock — fail-closed against a live holder, self-recovering after a crashed one; see [storage.md](storage.md#locking-and-shared-state-mutation)) before rereading and atomically replacing that map. Removing a package removes only that map entry; it never deletes a verified artifact as a side effect.

`LocalPackageInstallerV1` is the second writer of that same store, for a skill the user authored rather than a package a maintainer published. It parses the reserved `local-<platform>` ID, derives the compatibility window from the running runtime, and calls the unchanged `putVerifiedPackage` / `activate` pair. `putVerifiedPackage` already validates bytes → digest → parse → identity with no registry or signature dependency; only the registry installer binds it to a signed index by refreshing first. The factory orchestrator above it, `installLocalPlatformPackage()`, is structurally parallel to `exportPlatformPackageToTools()`: it audits the reviewed capabilities against the platform's active saved skills, projects them onto a package source through the shared `buildCapabilitySource()`, compiles them through the same `compilePublicPackageSource()` gate, persists the canonical reviewed source at `~/.klura/skills/<platform>/local-package.json` under the per-capability mutation lock, and installs the compiled bytes with that source's canonical-JSON digest as its local provenance. Execution safety is therefore byte-identical to the export path; what the local path lacks is distribution trust — signature, index validity, download digest, signed projection, release state — every element of which describes a publisher it does not have. Post-save proof freshness is advisory on this path: a stale or missing proof decorates the success envelope with a `_hint` instead of rejecting, because the bounded run is itself the verification. Nothing downstream changes: `InstalledPackageResolverV1`, login, sessions, run start, resume, daemon-boot recovery, cursors, and `remove_package` all treat a local artifact exactly as they treat a signed one.

The reserved `local-` prefix makes the two provenances structurally disjoint rather than conventionally separated. `parseRegistryPackageId` rejects it at the signed-index map key, the indexed `package_id`, the search cursor, the `show` selector, and the `install` selector — so a signed index carrying a `local-*` entry fails to parse, and `search_packages` / `show_package` / `install_package` return a typed `package_not_found` naming `list_installed_packages` rather than reaching the network. The review UI is driven by `RegistryIndexV1` and is therefore unreachable for a local package by construction.

`InstalledPackageResolverV1` rereads the active pointer for every operation, validates the installed runtime range before execution, verifies the content-addressed artifact again, and binds a selected public capability to that exact artifact. Internal helper capabilities are unavailable to direct consumer calls and runs. It never refreshes the registry or runs factory code.

`ConsumerCallServiceV1` is the local call facade used by adapters: its result is bound to the selected package ID, version, package digest, capability, and typed execution result. `--session` / `session_name` selects only a locally encrypted browser session for the matching declared authentication realm; it is validated structurally before target traffic. A session-pinned run records only that generation's realm, name, generation number, and digests in its immutable metadata; browser state itself remains in the encrypted session store. It resolves local state first and never refreshes or replaces an installed package during a call. Consumer call, run, and resume facades for one local home share one process-local origin scheduler, so separately constructed adapters do not create separate admission limits in the same process.

`bin/klura.js` is a lazy router. Root help is consumer-first; `klura factory --help` reveals discovery and authoring without changing any existing factory command spelling. The local consumer commands `search`, `show`, `install`, `installed`, `remove`, `call`, `run`, `export`, `runs`, `login`, `session`, and `doctor` load `consumer/cli` directly and do not initialize a daemon, browser, MCP host, or factory module. `search [query] [--cursor <opaque>] [--limit N]` performs deterministic signed-catalog lookup; `show <package[.capability]> [--version <version>]` reads a verified package without activating it; `install <package[@version]>` activates only that signed artifact. `installed [--cursor <opaque>] [--limit N]` returns package-ID-sorted pages from immutable local state; its cursor contains only its last structural sort key, so a later installation cannot invalidate an existing page traversal. None accepts a registry URL or signing key. The CLI constructs the compiled production registry authority directly, and it returns the ordinary typed `registry_unavailable` result only when that authority cannot provide a current verified index. `run <package.capability>` executes the installed collection contract; `--session <name>` pins its one locally encrypted browser generation until the terminal result, including a later resume. A required realm without an admissible named session yields a typed failure before target traffic. `run --detach` and `runs resume <run-id>` both hand terminal work to the daemon before the client waits, so a lost observer never cancels the run. Every CLI mutation creates one operation ID for its local daemon request. `runs wait <run-id>` subscribes to that daemon-owned terminal promise; cancelling the wait detaches only the observer. The MCP `wait_scrape_run` tool instead returns the current durable snapshot when no version is supplied, or waits once for a different `state_version`; it uses the run journal's filesystem event source and a bounded local one-shot timeout, never a polling loop. `runs cancel <run-id>` first appends a typed `cancel_requested` journal event, then aborts active work and reaches the ordinary terminal `cancelled` result. Startup terminalizes a run left after that durable request without resuming it or sending target traffic; when the durable ledger has items and a file output, it recreates and publishes the exact partial file before terminalization. One foreground `SIGINT` cooperatively terminalizes its run as `cancelled` and exits with code 130; a later interrupt uses the host default. `--input-mode <id>` selects one declared populated input mode; `--limit <id>=<n>` may be repeated to lower declared caller limits; neither flag can invent a mode or raise a signed bound. The CLI resolves `--output <path>` before IPC and gives the daemon an absolute file sink; `--format json|ndjson|csv` selects its representation (NDJSON is the default), and the same output contract works with `--detach`. CSV is available only where the signed collection contract declares its exact columns. `export <run-id> --output <path>` remains available to export a prior run. `login <package>` opens only the selected realm's signed local login browser and returns an interaction ID; `login complete <interaction-id>` verifies that same browser context and commits a new encrypted state generation only after its typed authenticated outcome. `session clear <package>` selects an authentication contract only when the package declares exactly one; otherwise its typed result lists the canonical contract IDs and leaves all local state unchanged. The historical CLI remains at `bin/klura-factory.js` and receives every other command unchanged.

The consumer entrypoint deliberately exports no unmediated raw network, browser, or factory helpers. Public package execution is built from signed contracts and scheduler-owned request paths; the one executable package profile runs reviewed source only inside its isolated, fail-closed browser boundary.

The shared local daemon loads its consumer adapter independently from factory state. It owns local registry calls, installed-pointer mutation and listing, active calls, run execution, run inspection, and the live scheduler snapshot; MCP and SDK clients only send closed IPC requests. `run_consumer_doctor` exposes exact active/queued counts and a structural contention reason per origin (`concurrency`, `rate_limit`, `minimum_delay`, or `circuit_open`) without guessing a release time or reading target response prose. Consumer execution requests carry their caller's cancellation signal into the shared scheduler and keep the daemon alive until their terminal result is durable; status checks and consumer-only traffic do not initialize discovery, agent, or browser state.

Before its IPC endpoint becomes ready, the daemon scans valid nonterminal local run journals and appends a typed `interrupted` event. That scan runs only after the daemon acquires its KLURA_HOME-wide singleton lock (`daemon.lock`, held until shutdown), so a second daemon instance refuses to start instead of appending recovery frames into journals a live daemon owns or unlinking its socket. `runs resume` accepts only that durable state; malformed journals remain quarantined for inspection rather than being rewritten or inferred from timing.

`parsePublicToolPackage()` binds a package's canonical manifest digest to strict package/capability metadata, JSON schemas, typed outcomes, traffic policies, authentication-realm declarations, closed request expressions, and the exact reviewed source exception above. A collection root names a declared page task, which may be an internal helper, and every task capability must use the collection capability's same authentication realm and safe-read strategies. An authentication realm declares its exact login URL, browser sandbox, traffic limits, and a structural check capability; it never contains a credential or package-controlled login action. Its executable profile admits node-owned HTTP JSON reads, runtime-owned browser-context HTTP, declarative browser navigation, and unauthenticated reviewed page programs with a complete browser-resource policy. An authenticated capability is browser-only; a required-auth capability returns `session_required` before any target traffic until a selected session is admitted. The runtime stores browser state in private encrypted immutable generations, compares the signed authentication-contract digest, and runs that realm's structural check in the same provisional browser context before the requested capability. That check has exactly one browser strategy and no automatic retry, so its policy can replace the login policy atomically while the browser remains isolated. A browser HTTP request needs both its bootstrap-navigation rule and an exact runtime-request rule, while navigation actions need exact interaction egress rules. Every other package shape is rejected rather than partially accepted. Later consumer profiles extend this closed union only with their corresponding runtime enforcement.

`ValueExpressionV1` has literals, caller-input pointers, prerequisite bindings, objects, arrays, string concatenation, explicit scalar-to-string conversion, URL/JSON/base64 encoding, and bounded SHA-256/HMAC operations. It has no code, property enumeration, implicit coercion, module, process, environment, timer, or network access. Type mismatch, missing pointer, missing binding, excessive AST size, crypto input, or encoded output fails closed.

`CollectionPredicateV1` is the separate signed predicate ABI for collection modes, pagination, fan-out, and declared outcome-array filtering. A predicate declares which JSON sources it may read and can use only pointer existence, JSON type, exact JSON equality, finite membership, array length, and boolean composition. It has no text matching, coercion, regular expressions, or implicit source access.

`ScrapeValueV1` is the companion AST for root inputs, continuation bindings, fan-out inputs, and item projection. It can read an allowed JSON pointer, retain a signed literal, add a bounded integer, or build bounded objects and arrays. Missing sources/pointers, non-integer arithmetic, and invalid AST shapes fail closed.

`StartUrlTemplateV1` is the closed URL grammar for a caller-provided scrape root. It fixes the HTTPS origin and literal path segments, permits only bounded single-segment slots, and allowlists sorted query keys with their value limits. The runtime canonicalizes a URL only after it passes that grammar; it never treats a caller URL as a free destination.

`ScrapeRunPolicyV1` declares every task, request, item, output, retry, time, memory, spool, and journal ceiling. `resolveEffectiveRunBounds` accepts only explicit caller bounds at or below those ceilings, plus declared caller limits; an attempted expansion or override of a fixed limit fails before a run exists.

`ScrapeInputModesV1` is a finite, ordered set of structural args predicates and roots. A root can run once or over one caller-provided array, and its task input can use only declared JSON data sources. A start URL is an explicit binding to one of the signed URL templates, never an unreviewed field in the input map.

`ScrapeTaskKindV1` models the finite traversal graph: read task, declared outcomes, item projection, bounded pagination, and acyclic fan-out. Pagination can only use structural task data/outcomes; fan-out can only receive a validated parent item. Neither surface accepts code, implicit links, or text interpretation. A declared semantic date cutoff is stricter still: it is available only for one once-seeded ordered page chain with no fan-out. Its caller bound is optional, but when present the runtime parses the declared ISO date, offset-required RFC 3339 instant, or safe integer exactly; it checks every emitted value and observed monotonic order without locale parsing, `Date` guessing, or lexical comparison. An invalid value or order is `item_invalid`; the first verified value outside the signed scope is not emitted and completes the run with `date_cutoff_reached`.

`ScrapeRunServiceV1` writes immutable digest-bound run metadata before target traffic. An inline run is admitted only when the compiler-proved item bound, at most 100 items, and a fixed result envelope fit the active adapter byte budget; otherwise it returns `output_sink_required` before creating metadata or sending traffic. The CLI and SDK adapter ceiling is 1 MiB, while the MCP adapter supplies its smaller structured-content ceiling. When a run uses a session, that metadata pins the exact encrypted generation by its structural reference and digest but never includes browser storage. A file-output declaration contains only a normalized absolute path and its declared format; before the run exists, its non-symlink parent and final, partial, and private run-owned sibling paths must be unused. The first journal frame names every complete initial root node through ordered data-spool references. Recovery validates and schedules that set directly, so a crash during root scheduling cannot omit an unrecorded root. It dequeues ready nodes in FIFO order and dispatches a bounded batch concurrently. Each node receives a durable output ordinal before enqueue; each item buffer records its node/page/item hierarchy position, while the committed ledger uses a contiguous item sequence. Recovery rejects a duplicate node ordinal, an out-of-order item commit, a sequence gap, or a sink prefix beyond the committed item sequence. The signed `max_reorder_buffer_bytes` and the largest signed outcome envelope can lower that batch bound; every non-leading chain reserves its maximum result envelope before target traffic and releases that reservation only when it receives its deterministic commit turn. Each batch commits its attempt observations, items, fan-out enqueue records, and node completions in deterministic dispatch order; each node's bounded pagination chain remains serial. A node becomes completed only after all of its child nodes have their own durable enqueue records. Resume recognizes each durable node ID and does not re-enqueue an already recorded fan-out child when it safely replays an interrupted parent. Ordinary journal work reserves five signed frames for terminalization before it dispatches further target traffic. The retained local state is charged globally across every concurrent chain: each identity digest and each parent item kept until its fan-out is durably materialized consumes the same signed local-state ceiling. A bound is reached as a typed run-budget outcome, never as an invalid item. Every emitted item is canonicalized, schema-validated, deduplicated by the signed identity pointers, appended to the local data spool, and committed through the hash-chained journal before it can reach a file sink. JSON, NDJSON, and declared CSV sinks fsync each valid prefix in a private sibling file; each fsynced item prefix then receives a hash-bound `sink_committed` frame, so recovery can distinguish the item ledger from the safe output prefix. A successful terminal descriptor records either `source_exhausted` or a typed `date_cutoff_reached` semantic-stop ID; both complete and publish an exact final output. Finalization binds that descriptor and file digest in `output_prepared`, publishes with no replacement, records `output_committed`, and only then writes the terminal frame. Startup completes that exact chain from the private sibling file rather than marking it interrupted. An incomplete terminal result uses the run-specific partial path. Explicit resume recreates that private prefix from the committed item journal before it can send target traffic. A `continue_independent` task failure preserves work from independent nodes but produces a typed partial result rather than a false success. The SDK start and resume inputs accept an `AbortSignal`, and each execution epoch has the signed total deadline: both reach the typed call boundary and stop new dispatches, but their terminal journal causes remain distinct as `cancelled` and `deadline_exhausted`.

The reorder allowance reserves the larger of the signed call envelope and the signed whole-page output ceiling for every waiting chain. A completed later chain can therefore persist validated `item_buffered` records before its turn, while only the fixed logical prefix receives item sequences, deduplication decisions, sink writes, and `item_committed` records. Every buffer record names its node/page/item position; a commit or duplicate resolution binds the same position. Safe-read resume rebuilds unresolved buffers from their verified spool records and rejects a replay that changes a position.

Every ordinary journal append also reserves five emergency frame bodies of 65,536 bytes plus their exact framing bytes. It is rejected before the write when it would consume that allowance; terminalization appends from the reserved portion and rejects an oversized emergency body. This applies independently of the ordinary frame-count reserve.

The package parser holds a collection's durable budgets to that accounting before the package can be installed. `parseCollectionRunPolicy` refuses a `max_journal_frames` below `minimumJournalFrames` — nine fixed frames (creation, output preparation, output commit, terminal, and the five-frame emergency reserve) plus five per task and three per item — and a `max_journal_bytes` below `minimumJournalBytes`, the emergency byte reserve plus a 1,024-byte allowance per frame. Both constants live in `public/contracts/journal-budget.ts`, the journal spends against the same numbers, and the run tests assert that a real run appends no more frames, and no larger frames, than the floor assumes. A stored run meta is parsed without these floors: its bounds were accepted at package parse time and may since have been lowered by the caller. When a run stops short, the cause is written beside the stop as a `stop_reason` frame — the failing check's own message, the node and task kind, bounded to 512 bytes — on the emergency path, since a cause matters most when the ordinary budget is what ran out. `runs show` surfaces the last one as `stop_reason`. A journal budget that runs out is a `run_budget_exhausted` stop; only an item the schema, identity, or size rules reject is `item_invalid`, and a continuation the page capability's input schema rejects is `task_failed`.

`readCommittedRunItems()` reconstructs the committed item sequence from the journal and verified spool references. `exportCommittedRunItems()` writes those records as canonical JSON, canonical NDJSON, or CSV projected solely through signed JSON pointers. It applies the signed output-byte ceiling and publishes a new file with a non-overwriting link only after the complete temporary file is durable. The in-process run result carries its run ID and summary, never an unbounded item array.

`inspectStoredRun()` reads the immutable metadata plus hash-chained journal. Its terminal classification is structural: the first frame must bind that metadata, a terminal frame must be unique and final, and its result shape is closed. Absence of a terminal frame is reported only as `nonterminal`; the reader never invents a completion, interruption reason, or resume outcome. `RunStoreV1.listRunIds()` returns only regular local run directories with canonical IDs.

`JournalEventV1` is a closed union. The current durable records cover creation, lifecycle state, enqueued nodes, attempt intent/observation, accepted task completion, item buffer/commit/deduplication, independent task skips, and terminal results. An accepted task can be recorded only once for its observed attempt; an item commit must name its own prior buffer; and a duplicate must name a prior committed identity. Those accounting records make a resumed run's result summary reconstructible from durable facts rather than from a fresh request or a response interpretation. An unknown key, unsupported event, invalid counter, or malformed blob reference makes a recovered journal corrupt; readers do not interpret arbitrary event JSON.

Every enqueued node has a deterministic `node_v1_…` ID derived from the run ID and canonical logical key. Its complete bounded node state is appended to the private data spool before the event commits a matching blob reference and key digest. The frontier is therefore recoverable from durable data rather than from reconstructed request text or a platform-specific heuristic.

Attempt intent and observation, independent skips, and successful completion each bind that same node ID. A recovery reader can therefore classify a node from declared journal state: pending, with an attempt lacking an observation, skipped, or completed. It never derives that state from elapsed time or an HTTP status.

`recoverRunState()` is the recovery gate. It verifies every node ID against the enclosing run and its canonical logical key, checks node-event fields against the durable node state, and requires all accepted node/item blobs to form one contiguous, digest-valid spool prefix. It sends no traffic. Once that prefix is verified, it durably discards only a trailing spool suffix that no accepted journal frame references; a malformed reference or lifecycle transition is a typed local recovery error.

Its resume preflight is equally structural. A terminal run is ineligible. An unresolved attempt is replayable only when its exact task capability is still present in the immutable collection and every declared strategy is `safe_read`; resume writes a `node_replay_authorized` event in its new execution epoch before it can dispatch that same durable node input again. Any other unresolved attempt remains `unknown_attempt` and is ineligible. No decision reads elapsed time, response prose, status codes, or page text.

After every accepted page that continues pagination, the runtime writes a new `node_progressed` blob before dispatching the next page. It contains the next validated input, every canonical input digest already seen in that chain, and the consumed page count. A resumed chain therefore starts from the saved structural continuation, never from a guessed cursor or the root input.

`ScrapeRunServiceV1.resume()` first acquires a local per-run lease, reconstructs the durable accounting and pending frontier, then appends the next execution epoch before it sends any target traffic. The lease rejects a live concurrent process and permits recovery only after its recorded local owner is gone. The immutable artifact stores both its package digest and the signed runtime range selected at install time; resume verifies that range before it loads the capability. It resolves the package by that digest, not by the current `installed.json` pointer, so a later package update cannot silently change what a resume executes. `klura runs resume <run-id>` exposes that same flow.

`ConsumerRunServiceV1` provides `show()`, cursor-paged `listPage()`, bounded `items()` access, and one-shot state waits. Every inspection carries `state_version`, the highest durable journal sequence it applied. A state wait returns immediately when no prior version is supplied or the current version differs; otherwise it listens to the exact journal file and returns either its next durable snapshot or `changed:false` after one local timeout (0–25 seconds, default 20). It never infers progress from elapsed time or polls the file. Run pages sort by immutable `(created_at, run_id)` and retain a valid cursor when a later run is added; a page that cannot fit the adapter limit returns typed `output_too_large_for_adapter`. Item pages use the durable `item_committed` journal sequence as an exclusive cursor and read no target site. A valid metadata file paired with a corrupt journal becomes a small `quarantined_run` entry during a list, so it cannot hide other runs; direct `show()` and `items()` still reject the corrupt state. Daemon-backed `show`, `items`, `wait`, and `discard` normalize an absent run to `run_not_found` and a corrupted local run state to `local_state_invalid` instead of leaking an IPC rejection. `discard()` removes only that already-quarantined run and leaves valid active, interrupted, and terminal runs intact. `klura runs discard <run-id> --yes` is the explicit destructive CLI form. `klura runs list [--cursor <opaque>] [--limit N]`, `klura runs show <run-id>`, `klura runs items <run-id> [--after-sequence N] [--limit N]`, and `klura runs resume <run-id>` are lazy consumer routes.

`klura runs items <run-id> --follow --format ndjson` holds one local daemon stream open. It reads only committed journal items in contiguous sequence order, wakes through the journal's filesystem event source rather than a timer, and ends with one canonical `end` or `failure` event. Observer cancellation closes only that stream and does not cancel the run.

`JsonSchemaV1` is a canonical subset: finite scalar types, arrays with one item schema, and objects with declared properties plus `additionalProperties:false` or a schema-valued bounded map. It rejects `$ref`, formats, defaults, coercion, executable keywords, unknown keys, and unbounded maps.

`OutcomeContractV1` uses only structural facts: status, normalized headers, body kind, exact media type, JSON pointers, array sizes, declared DOM selectors, and empty-body state. A projection may map an exact JSON-array pointer through a declared `raw_item` predicate and `ScrapeValueV1` field map; it never searches text, guesses item shape, or runs package code. A scalar call becomes a verified result only when exactly one case matches, its projection fits the output schema and signed byte ceiling, and its assertions pass. An assertion may compare one output pointer either with one input pointer or with a closed input-only value expression; it cannot read a secret binding or response prose. A 2xx response, response wording, or a missing selector is never treated as success or absence.
